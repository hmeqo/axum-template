# Axum Template

Rust Axum web API template with Toasty ORM, session & JWT auth, RBAC, file uploads.

## Quick start

```bash
# Start PostgreSQL, then:
./manage migrate          # create tables
./manage init             # seed roles/permissions
./manage create-superuser # create superuser

# Start server
cargo run --bin axum-template

# Or hot-reload
./manage dev
```

Building the RPC surface needs `protoc` on `PATH` (generated by `build.rs`).

Default database: `postgres://postgres:@localhost:5432/db`.
Config is read from `.axum-template/config.toml` (or the XDG config dir); see `docs/configuration.md`
for environment layering, every key and its default.

## Endpoints

| Endpoint                              | Auth                                   | Description                                                             |
| ------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------- |
| `POST /api/auth/login`                | —                                      | Login via username/password, sets cookie                                |
| `GET /api/auth/me`                    | session or JWT                         | Current user info (cookie or bearer token)                              |
| `PUT /api/auth/password`              | session or JWT                         | Change own password (the credential is the subject)                     |
| `POST /api/auth/logout`               | session                                | End this session                                                        |
| `GET /api/auth/sessions`              | session                                | List this account's sessions (current one flagged)                      |
| `DELETE /api/auth/sessions/{id}`      | session                                | Revoke one of this account's sessions                                   |
| `POST /api/auth/sessions/revoke-others` | session                              | Revoke every session of this account except this one                    |
| `POST /api/auth/jwt/login`            | —                                      | Login, returns `access_token` + `refresh_token`                         |
| `POST /api/auth/jwt/refresh`          | —                                      | Rotate tokens                                                           |
| `POST /api/auth/jwt/logout`           | JWT                                    | Revoke refresh tokens                                                   |
| `POST /api/files`                     | session or JWT (`user:write`)          | Upload a file (multipart field `file`)                                  |
| `GET /api/files`                      | session or JWT (`user:write`)          | List your own files, newest first, paginated                            |
| `POST /api/files/{id}/attach`         | session or JWT (`user:write`)          | Mark an uploaded file as attached                                       |
| `GET /media/{id}`                     | —                                      | Download an uploaded file: a raster original renders in place, any other type is an attachment; `?size=N` (64/128/256/512/2048) serves a derivative as AVIF or JPEG by `Accept` |
| `GET /api/users`                      | session or JWT (`user:read`)           | List users                                                              |
| `POST /api/users`                     | session or JWT (`user:write`)          | Create user                                                             |
| `GET /api/users/{id}`                 | session or JWT (`user:read`)           | Fetch one user                                                          |
| `PUT /api/users/{id}/username`        | session or JWT (`user:write`)          | Rename user                                                             |
| `POST /api/users/{id}/password/reset` | session or JWT (`user:reset-password`) | Reset another user's password: no old password, revokes them everywhere |
| `DELETE /api/users/{id}`              | session or JWT (`user:delete`)         | Delete user                                                             |
| `GET /ws`                             | session                                | Realtime sample: subscribe to a topic; session revocation closes the socket |
| `POST /api/rpc/{package}.{Service}/{Method}` | session or JWT                  | ConnectRPC surface generated from `proto/` (see below)                  |
| `GET /api/error`                       | —                                       | Error-contract sample: the error shape generated clients emit            |
| `GET /health`                         | —                                      | Liveness probe                                                          |
| `GET /health/ready`                   | —                                      | Readiness probe (database reachable)                                    |

Interactive docs: `/api-docs/scalar` (no trailing slash — the mount is an exact path) and
`/api-docs/swagger-ui` (redirects to the trailing-slash form); the raw document is
`/api-docs/openapi.json`.

## RPC (ConnectRPC)

The contract is `proto/template/v1/template.proto`. `build.rs` generates the messages, the service and
the descriptor set from it, so the code and the published schema cannot drift; `protoc` must be on
`PATH` to build.

| Transport | Route |
| --- | --- |
| Connect / gRPC / gRPC-Web | `POST /api/rpc/{package}.{Service}/{Method}` (bearer token or session cookie) |
| Schema | gRPC server reflection at `/api-docs/rpc/grpc.reflection.v1.ServerReflection/ServerReflectionInfo` — public like the REST document, bidi so HTTP/2, served from the same descriptor set |

The wire format is proto3 JSON: 64-bit integers travel as strings (`"total": "2"`, `"id": "1"`) and
multi-word fields are camelCase (`perPage`, `createdAt`). The schema lives beside the REST document, so
a client that only takes `host:port` needs the full base URL.

Methods live in `app/rpc/service.rs` and go through the same three steps as the REST handlers:
identity from the request extensions the group auth layer filled, one permission check where the REST
side writes `Require<P>`, then one service call. Streaming features with their own transport belong on
their own route — see `docs/architecture.md`.

## Commands

```bash
./manage migrate                              # run pending migrations
./manage fresh                                # drop & recreate tables
./manage init                                 # seed default roles/permissions
./manage create-superuser                     # prompts for credentials
./manage migration-generate --name xxx        # diff models → SQL
```

## Stack

| Layer      | Choice                                    |
| ---------- | ----------------------------------------- |
| Web        | Axum 0.8                                  |
| ORM        | Toasty 0.10                               |
| Auth       | Session (cookie) + JWT (`jsonwebtoken`)   |
| DB         | PostgreSQL                                |
| Migrations | `toasty-cli`                              |
| Docs       | utoipa + Scalar / Swagger UI              |
| RPC        | ConnectRPC 0.9 (+ gRPC reflection), `buffa` |
